# Endless Clay

A multiplayer world-building sandbox where everything is clay. It runs in VR and in passthrough mixed reality (AR) on Meta Quest 3 and 3S, on flat screens in any modern browser, and comes with a phone companion app, **Endless Clay Link**. It's a WebXR progressive web app: the website is the game, and the Quest app (APK) is a thin wrapper that opens it straight into the headset.

## 1. The website: GitHub Pages

This folder is the whole site. It lives in the repository **`noireal-tech/noireal-tech.github.io`**, a GitHub "user site": GitHub serves it at `https://noireal-tech.github.io`, with HTTPS, for free, from the `main` branch.

- A user site serves from the **root of the domain**, which the Quest app needs (`/.well-known/assetlinks.json` has to be at the root). A project site (`noireal-tech.github.io/something`) wouldn't work.
- `.nojekyll` stops GitHub from hiding the `.well-known` folder.
- To check it: Settings ▸ Pages should say "Your site is live at https://noireal-tech.github.io", and <https://noireal-tech.github.io/.well-known/assetlinks.json> should open.
- **Updating the game:** commit changed files to `main`. GitHub republishes in about a minute. Players get the new version the next time they open the app (the offline cache swaps in the new files in the background).

## 2. The Quest app (APK): built by GitHub Actions

The APK is built on GitHub's machines, free for a public repository, so you never need Android Studio or Java.

**One-time setup: add the signing key as two repository secrets.** You keep the key files (`android.keystore`, `keystore-base64.txt`, `keystore-password.txt`). They are never in this repository.

1. Repository ▸ **Settings ▸ Secrets and variables ▸ Actions ▸ New repository secret**.
2. Name `ANDROID_KEYSTORE_BASE64`, value: the whole contents of `keystore-base64.txt`.
3. Name `ANDROID_KEYSTORE_PASSWORD`, value: the contents of `keystore-password.txt`.

**Building:**

- **A test build:** Actions ▸ **Build Quest APK** ▸ **Run workflow**. When it finishes (about 5 minutes), download `endless-clay-apk` from the run's page.
- **A release:** push a tag such as `v1.0.0` (or create a release with that tag on GitHub). The workflow builds it and attaches `endless-clay.apk` to the release. SideQuest's GitHub integration picks up new releases.
- The workflow refuses to finish if the APK's signature doesn't match `.well-known/assetlinks.json`, because such an APK wouldn't open.

**Installing it on your own Quest:** with SideQuest's desktop or headset app (drag the APK in), or `adb install endless-clay.apk`. It appears under Unknown Sources (or in the main library when installed through the SideQuest app).

**When you need a new APK:** rarely. Game changes reach players through the website. A new APK is only needed for a new name or icon, different Quest permissions, or a new Bubblewrap version. Then raise `versionCode` (and `versionName`) in the source's `release/release.json`, run `node release/make-android.js`, commit the new `android/` folder and tag a release.

**Quest settings baked in:** opens straight into the headset (immersive mode), with passthrough while it loads; asks for spatial data ("USE_SCENE") so AR can find tables and floors; no notifications, no microphone (the game itself doesn't record).

## Keeping players' worlds safe

Worlds, photos, sounds and settings live on each player's device, in the browser storage that belongs to the website's address. Some rules keep them safe:

- **The address never changes.** Storage belongs to `https://noireal-tech.github.io`. Moving the game to another address (even your own domain later) would start everyone with empty storage. Players can carry worlds across with **Save world file** and **Open world file**, but it's best never to move. So:
  - Don't rename the `noireal-tech` GitHub account or the `noireal-tech.github.io` repository.
  - Don't add a custom domain to this site. If you ever want one, ask first: it can be done with an export-and-import step.
- **Persistent storage:** both apps ask the browser to keep their storage even when the device is short of space, so it isn't cleared automatically.
- **Backups:** **Save world file** (⋯ menu) writes a `.clay` file the player keeps. Worth suggesting to players before big builds.
- **The signing key and the package ID never change.** Every APK update must be signed with the same key, or it can't install over the old one. Keep `android.keystore` and its password in two safe places (a password manager, and an offline copy). Losing it means a new package ID and a fresh start for every APK player.
- **The source code** lives in the private repository `noireal-tech/endless-clay-source` (with the tests and build scripts), so nothing depends on any one computer.

## How the app behaves on the Quest

- **Launch:** opens straight into the headset, in whichever mode was used last (VR the first time).
- **Control panel:** a four-sided panel you turn by category, on your left wrist in VR and at the bottom of the flat screen. Undo, Redo and Snap are on every side.
  - **Create & Construct:** modelled on Open Blocks' tools. Sculpt (build, carve, groove, pull, slice, flatten, smooth, coil), Shapes (sphere, cone, cube, cylinder, torus, gem, brick, select, move, erase, paste, billboard), Paint (glaze, recolor, pick color, skin), Edit (size, stretch, distort, turn, flip, duplicate, group), Places and Room (VR/AR). **Cast solid / Cast hollow** sets whether new molds come out solid clay or a thin hollow shell.
  - **Sounds & Images:** your photo skins, sounds (put them on shapes, scene sound, tool sounds) and scenes, including 360° skies.
  - **Social links:** the links you've added, ready to place as billboards, and the controls for the picked billboard.
  - **Phone:** the phone link, with its code and QR.
  - **Hiding:** the ⌄ button or the **I** key hides the flat-screen panels (Show panels brings them back). Tab moves between buttons, like any web page. In VR, hold Y (or press Hide panel) to hide or show the wrist panel; a quick tap of Y still switches walk/fly.
- **Billboard links:** framed windows on posts and videos from YouTube, Instagram, Facebook, TikTok, Threads and Snapchat. Paste a link into **Social links** (or send it from the phone app's Links tab), press **Place** and point where it should go.
  - Choose **Stick to shapes** (it rides along when the shape moves, turns or resizes) or **Fixed in space**, before placing or afterwards with Attach / Fix in space.
  - Pick a billboard with Select (or click it in the Social links list) to resize it (smaller, bigger, 16:9, 9:16, square, post), move it (◀ ▶ ▲ ▼, nearer, back), turn it, or delete it. It then stays exactly where you left it, and is saved and shared like any shape.
  - **Plays on click** or **Plays when near**: auto-play starts muted when you walk within about 6 m and stops when you walk away. Closing one with × keeps it closed until you've left and come back. Up to three play at once.
  - **On the flat screen** the platform's own player plays inside the frame in the world. **In VR and AR** the Quest Browser can't show web pages inside the headset view, so a billboard shows a preview card there; clicking it leaves the headset view and plays the post on the flat screen, with **Back to VR** (or Back to AR) to return. Auto-play applies on the flat screen only.
  - Each platform decides what can be embedded: private posts, age-restricted videos or posts whose owners turned off embedding show the platform's own message instead. TikTok short links (vm.tiktok.com) need opening once in a browser to get the full link. Snapchat and Threads embeds use their public embed pages and may change if those platforms change them.
- **Saving and sharing:** the ⋯ menu on the flat screen saves a world file (.clay) you can back up or send to a friend, opens one, and exports the clay as an OBJ model (with colours) for other 3D apps.
- **Crystal:** the ninth colour turns a shape, or a whole group, into see-through crystal. Recolor with Crystal for clear glass; Glaze or Recolor a crystal shape with any other colour to stain it, like stained glass. The Edit panel's **Crystal** switch turns a shape to crystal (or back to clay) and keeps its colours as the tint. The land always stays clay, so on the land Crystal paints Porcelain.
- **Skins (photos on shapes):** take a photo with the camera, choose one from the device's pictures, or take a **Snapshot** of what you're looking at, then put it on a shape or a whole group. Use the Look page of the Edit panel (flat screen), the wrist panel's **Skin** page in VR, or the **Skin** tool (Paint) and point at a shape. Fits: **Wrap** (across the front, mirrored round the back), **360°** (once all the way round, no mirroring), **Box** (one on each side) or **Front** (straight through). The **Photo** buttons move the photo (◀ ▶ ▲ ▼), turn it (⟲ ⟳), size it (− +) or **Reset** it. **Land skins:** point the Skin tool at the land to lay the photo down on the ground, or on a cliff like a mural (brush size sets how big). Point at a land skin to pick it, then move, turn or size it with the same Photo buttons, or Remove skin. Land skins follow the land as you sculpt it, and show on the AR board too. Skins stay put while you move, resize, sculpt or distort the shape, work on Crystal shapes too, and travel with copies, saves, world files and multiplayer rooms. The last 8 photos stay on the device for any world.
  - Camera photos use the browser's camera access. In the headset, the app tries the Quest camera; if the Quest Browser doesn't allow it, take camera photos on the flat screen and they appear on the VR Skin page. Photos you put on shapes are shared with everyone in your room and saved in the world.
- **Phone link (Endless Clay Link):** a companion app for your phone that sends photos, 360° skies, sounds and social links to the headset. In the game, turn the panel to **Phone** (or ⋯ ▸ **Phone link**) and turn the link on. It shows a 6-letter code and a QR code; scan the QR with your phone (or open `phone.html` on your site) and the phone links. On the phone, tap Share ▸ Add to Home Screen (iPhone) or Install (Android) to keep it as an app.
  - **Photos** go to your Skin photos (and straight onto selected shapes). They're sent at the size the headset keeps them (512 px), so they arrive in a second or two and are compressed only once.
  - **Skies:** a 360° photo becomes a new scene, wrapped all round you, and the lighting matches it. Panoramas and ordinary photos work too (sky and ground are filled in, or the photo is mirrored round). Pick skies any time under Sounds & Images ▸ Scenes. **High quality** (on the Skies tab) sends 4096 × 2048 instead of 2048 × 1024: much sharper all round you, up to four times bigger to send. Skies added from a file on the headset itself are always high quality.
  - **Sounds:** record up to 30 seconds or pick a file, then edit it before sending: drag **Start** and **End** to trim it (up to a minute can go), **Even out the volume** (its loudest point at about −1 dB), **Smooth loop** (the end is blended into the start so a loop has no click or jump; on by default for scene sounds), and **Preview** to hear exactly what will be sent. Edited sounds go as a WAV; unedited ones go as recorded. Then choose what it's for: **Shapes** (put it on shapes from the edit panel's **Look** tab; it plays when you touch or tap the shape, or **loops** softly from the shape when you're near), **Scene sound** (loops quietly in the background of the current scene), or a **tool sound** (Build, Carve, Smooth, Brick or button taps).
  - **Links:** paste a link to a post or video (Share ▸ Copy link in the social app); it lands in the headset's Social links, ready to place as a billboard.
  - **Share to it from other apps (Android):** once the phone app is installed, it appears in other apps' Share menus. Share a photo, a sound, or a YouTube/TikTok/Instagram/Facebook/Threads/Snapchat link to **Clay Link**: photos and links go straight into the queue, a 360° photo opens as a sky, a sound opens in the editor. If you're not linked yet, they wait and go as soon as you are. iPhones don't let web apps receive shares, so on an iPhone use the paste box and file pickers.
  - **On your headset:** once linked, **Show what's there** lists the headset's skies, sounds, social links and photos. Rename skies and sounds, or delete any of them (tap Delete twice). Deleting a photo or sound here doesn't remove it from shapes that already wear it in a world.
  - **Dependable sending:** while anything is sending, the phone keeps its screen on (a sleeping phone drops the link). If the link drops anyway, the item carries on from where it stopped when the link is back, rather than starting again, and nothing arrives twice. Phones that can, buzz briefly when an item lands.
  - **Recent headsets:** the last five headsets you linked to are shown under the code box; tap one to link again.
  - Skies and sounds are kept on the headset in its media library. Sounds you put on shapes are part of the world: everyone in your room hears them, and they're saved with it. Scenes, scene sounds and tool sounds are your own settings.
  - The phone needs an internet connection, like rooms do: the link uses the same signalling server. On mobile data it usually also needs a relay (see "Relay (TURN) server" below).
- **Ground arrows and walk view (phones):** on a phone the camera sits a little behind and above you (**View: behind you**), and you stand on the ground in the middle of four Street View-style arrows: forward, left, right and back. They turn with you.
  - Tap an arrow to step about 3 m that way, or hold it to keep walking (let go to stop). Dragging from an arrow still looks round. If clay or a hill is in the way, the arrow turns salmon and won't step. The camera frames you and the ring between the top bar and the panel, and comes closer if clay is behind you.
  - **Joystick = height:** with the arrows on, push the joystick up to rise (it starts flying), down to come back down (touching the ground walks again), and sideways to turn. The Up/Down buttons step aside.
  - ⋯ ▸ **Ground arrows** turns them on or off (with them off, the joystick walks as before). ⋯ ▸ **View** switches between behind you and through your eyes; through your eyes, the arrows sit just ahead instead. Both are on by default on phones and tablets, off on computers, and remembered. Neither shows in VR or AR, and they're left out of snapshots.
- **Tourist view:** for walking round and exploring a world without editing it. The tools, undo/redo and the panel's making pages go away; you keep moving, flying, places, sizes, scenes and playing billboards. In VR the wrist panel becomes one Tourist view side (Places, Scenes, Room).
  - **Choosing it:** ⋯ ▸ **Tourist view**, say to hand your phone or headset to someone. **Leave tourist view** brings the tools back.
  - **Visitors to your world:** whoever hosts a room owns that world. People who join are tourists unless the owner turns on **Visitors can build** (Play together card, before or during the room; it starts off). Turning it on or off applies straight away. The host enforces it: edits from visitors are dropped when building isn't allowed, so a modified app can't change your world either.
- **Copy, Group copy, Paste:** Copy puts the selected shapes on a clipboard; Group copy takes the whole group(s) and keeps them grouped. The Paste tool (Shapes) stamps the clipboard wherever you point, as many times as you like, each paste a fresh set of shapes or a fresh group. Copies keep everything: sculpting, size level, crystal, the photo skin and where it sits, and the shape's sound. The clipboard stays on the headset between sessions and worlds. Keyboard: Ctrl+C, Ctrl+Alt+C, Ctrl+V.
- **Shape size levels:** a selected shape (or group) sizes along 25 levels, each double the one before. Level 7 is a normal mold (0.8 m), level 1 is about 1.25 cm and level 25 about 210 km. Use the slider or −/+ on the Edit panel, the 25-step bar on the wrist panel, = / − on a keyboard, or hold the right grip and push the right stick up or down.
- **Places and size:** the wrist panel's Places tab (and the pin button on the flat screen) has Start plus four places you can mark. Each place remembers where you stood, which way you faced, and your size in VR (Tiny, Normal, Big, Giant) or the board scale in AR. Clicking the right thumbstick cycles Start → your places → Start.
- **Switching:** the Room page of the left-wrist panel has **Switch to AR** / **Switch to VR**. If the headset doesn't allow the switch on its own, the app drops back to its flat screen with **Enter VR** and **AR** buttons.
- **Saving:** worlds, names and settings are saved on the headset.
- **Editing a shape on a phone:** the edit sheet takes the tray's place while something is selected, so the shape stays in view and the joystick, Up/Down and ground arrows don't move. **Done** (or tapping away) brings the tray back. The sheet has five tabs: Size, Distort, Turn, Arrange (with the colours, for Recolor all) and **Look** (photo skin and sound together). On wider screens the sheet sits at the side instead.
- **Foldable phones (Pixel Fold and similar):** closed, the cover screen gets the phone layout. Opened flat, the inner screen gets the wide layout (edit sheet at the side, the world in view). Half-folded, nothing sits on the crease:
  - **Like a book** (fold upright): the world fills the left page; the top bar, the tray and the edit sheet stack on the right page, with the sheet above the tray. The joystick stays on the world's page.
  - **On a table** (fold across, like a laptop): the world stands up on the top half; the joystick, the tray and the edit sheet lie on the bottom half, where your fingers are.
  - It switches as you fold and unfold, mid-edit too. The phone app does the same: two columns opened flat, one column per page like a book, and on a table what's arrived on the top half with the sending controls on the bottom half. This uses Chrome's foldable support (viewport segments, Chrome 138 or later on Android).
- **Easier to see and use:**
  - Text follows the device's text size (iPhone's Text Size setting; Android and browser zoom). The tray rearranges itself as text grows (two-line tabs, then fewer columns, then it scrolls), so nothing goes off screen up to 200%. The top bar grows to 150% and then wraps.
  - Every button shows a press tint the moment you touch it. On touch screens, tap areas reach 44 points (the colour circles are bigger, and their tap areas fill the gaps around them). Sliders have fingertip-sized handles.
  - **Increase Contrast** (iPhone, Android's high-contrast text, or the browser's contrast setting) brightens secondary text and gives buttons 3:1 outlines. **Reduce Transparency** makes the panels solid.
  - **Motion:** follows the device's Reduce Motion setting, or choose ⋯ ▸ **Motion: reduced**. Reduced: the panels switch without turning (flat screen and wrist), the snapshot flash is soft, and ground arrows step under a quick fade instead of gliding (holding an arrow repeats the step).
  - In VR, pressing a wrist-panel button now flashes it, alongside the tap sound and the controller pulse.
- **Updates:** upload new files to your host. The headset picks them up when it next launches with a connection. You only need a new APK if you change the app's name, icon or package details.

## Multiplayer before release

Room codes connect players directly. The host's world is the shared one, and the host decides whether visitors can build or only explore (see Tourist view). If a guest's connection drops (a phone changing networks, say), it rejoins by itself and reloads the shared world; it tries for about half a minute before giving up. Every device checks what arrives (and what it loads from a save), so a damaged or hostile message is ignored instead of breaking the room or the world.

Two kinds of server help devices reach each other. Both are set in `js/config.js`, which the game and the phone app share (rebuilding with `build-app.js` keeps your `config.js`):

- **The link (signalling) server** introduces devices to each other. For testing, the app uses PeerJS's free public one; it's a shared service with no guarantees. For a released app you can run your own (the open-source `peer` server, `npm install peer`, on any small Node host) and add `host`, `port`, `path` and `secure: true` to `ENDLESS_CLAY_PEER_SERVER`.
- **A relay (TURN) server** carries the traffic when two devices can't connect directly. That's the next section, and it matters more.

## Relay (TURN) server

**Why you need one.** Devices try to connect directly. That works on most home Wi-Fi, but often fails when one side is a phone on mobile data, a school or office network, or some home routers: the link just never opens ("Lost the headset", "Could not reach…", or stuck on Linking). A TURN server relays the data in those cases. It's only used when a direct connection fails, so most traffic still goes device to device.

Pick one route. A and B need no server of your own.

### Route A: Metered (managed, quickest, free for small use)

Metered's TURN service gives 20 GB a month free with an account (plenty for a small group: a photo is about 60 KB, a sky 1–4 MB).

1. Create a free account at <https://www.metered.ca/stun-turn> and create a TURN credential in the dashboard.
2. Either paste the ICE server list it shows you (the **Instructions** button) into `js/config.js`:

   ```js
   window.ENDLESS_CLAY_PEER_SERVER = { config: { iceServers: [ /* paste Metered's list here */ ] } };
   ```

   or, to fetch fresh credentials each time, use its credentials address with your API key:

   ```js
   window.ENDLESS_CLAY_ICE_URL = 'https://YOURAPP.metered.live/api/v1/turn/credentials?apiKey=YOUR_API_KEY';
   ```

3. Upload `js/config.js` to your host (and to the phone app's host, if different). Done.

The credentials are visible to anyone who opens your page (all web apps are like this); Metered's dashboard shows usage, and you can rotate credentials there.

### Route B: Cloudflare (managed, for more users)

Cloudflare's TURN gives 1,000 GB free, then $0.05 per GB. Its credentials must be made on a server and last at most 48 hours, so you add a tiny Cloudflare Worker that hands them out.

1. In the Cloudflare dashboard, find **Realtime** (formerly called Calls) and create a **TURN key** (Cloudflare's guide: <https://developers.cloudflare.com/realtime/turn/generate-credentials/>). Note its **Key ID** and **API token**. The token is secret: it goes in the Worker, never in `config.js`.
2. Create a Worker (Workers & Pages ▸ Create ▸ Worker) with this code, and add two secrets in its settings: `TURN_KEY_ID` and `TURN_KEY_API_TOKEN`. Replace `https://your-site.example` with your app's address.

   ```js
   export default {
     async fetch(request, env) {
       const r = await fetch(`https://rtc.live.cloudflare.com/v1/turn/keys/${env.TURN_KEY_ID}/credentials/generate-ice-servers`, {
         method: 'POST',
         headers: { Authorization: `Bearer ${env.TURN_KEY_API_TOKEN}`, 'Content-Type': 'application/json' },
         body: JSON.stringify({ ttl: 86400 })
       });
       return new Response(await r.text(), { status: r.status, headers: {
         'Content-Type': 'application/json', 'Cache-Control': 'no-store',
         'Access-Control-Allow-Origin': 'https://your-site.example' } });
     }
   };
   ```

3. In `js/config.js`: `window.ENDLESS_CLAY_ICE_URL = 'https://YOUR-WORKER.YOUR-ACCOUNT.workers.dev';`

The app keeps the answer for half an hour and leaves out Cloudflare's port-53 addresses, which browsers block.

### Route C: your own server (coturn)

Full control, a fixed monthly cost, no per-GB charges. You need a small Linux server (any VPS with a public IP; 1 CPU and 1 GB RAM are plenty) and a domain name you control. These steps are for Ubuntu or Debian.

1. **Name it.** Point a DNS name such as `turn.example.com` at the server's public IP (an A record).
2. **Install:** `sudo apt update && sudo apt install coturn certbot`
3. **Certificate** (for encrypted `turns:`, which gets through strict networks on port 443/5349):

   ```sh
   sudo certbot certonly --standalone -d turn.example.com \
     --deploy-hook "cp /etc/letsencrypt/live/turn.example.com/fullchain.pem /etc/letsencrypt/live/turn.example.com/privkey.pem /etc/coturn/ && chown turnserver:turnserver /etc/coturn/*.pem && systemctl restart coturn"
   ```

   (Port 80 must be open for this step. The hook copies the certificate where coturn can read it, now and at every renewal.)
4. **Configure.** Replace `/etc/turnserver.conf` with the following, changing the name, IP and password (make the password long and random, e.g. `openssl rand -hex 24`):

   ```ini
   listening-port=3478
   tls-listening-port=5349
   external-ip=YOUR.PUBLIC.IP
   realm=turn.example.com
   fingerprint
   lt-cred-mech
   user=clay:YOUR-LONG-RANDOM-PASSWORD
   cert=/etc/coturn/fullchain.pem
   pkey=/etc/coturn/privkey.pem
   min-port=49152
   max-port=65535
   no-tlsv1
   no-tlsv1_1
   no-cli
   no-multicast-peers
   # keep it from being used to reach private networks
   denied-peer-ip=10.0.0.0-10.255.255.255
   denied-peer-ip=172.16.0.0-172.31.255.255
   denied-peer-ip=192.168.0.0-192.168.255.255
   denied-peer-ip=127.0.0.0-127.255.255.255
   denied-peer-ip=169.254.0.0-169.254.255.255
   # limits, so a leaked password can't run up your bandwidth: at most 100 relayed connections at once, 3 MB/s each
   total-quota=100
   max-bps=3000000
   ```

   If the server sits behind NAT (some clouds give it a private address), use `external-ip=PUBLIC.IP/PRIVATE.IP`. If the file `/etc/default/coturn` exists, set `TURNSERVER_ENABLED=1` in it.
5. **Open the ports** in the server's firewall and your cloud provider's security group: 3478 UDP and TCP, 5349 TCP, and UDP 49152–65535. With ufw:

   ```sh
   sudo ufw allow 3478/udp && sudo ufw allow 3478/tcp && sudo ufw allow 5349/tcp && sudo ufw allow 49152:65535/udp
   ```

6. **Start it:** `sudo systemctl enable --now coturn` (and `sudo systemctl restart coturn` after any config change; `journalctl -u coturn` shows its log).
7. **Tell the app,** in `js/config.js`:

   ```js
   window.ENDLESS_CLAY_PEER_SERVER = { config: { iceServers: [
     { urls: 'stun:turn.example.com:3478' },
     { urls: ['turn:turn.example.com:3478?transport=udp', 'turn:turn.example.com:3478?transport=tcp', 'turns:turn.example.com:5349?transport=tcp'],
       username: 'clay', credential: 'YOUR-LONG-RANDOM-PASSWORD' }
   ] } };
   ```

**The password is public.** Anything in `config.js` can be read by anyone who opens your site, so treat this password as a key that keeps out casual misuse, not a secret; the quotas above cap the damage. For proper protection, switch coturn to expiring credentials: replace `lt-cred-mech` and the `user=` line with `use-auth-secret` and `static-auth-secret=A-LONG-SECRET`, and hand out credentials from a Worker (like Route B's) that signs them:

```js
export default {
  async fetch(request, env) {
    const user = `${Math.floor(Date.now() / 1000) + 86400}:clay`; // valid for a day
    const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(env.TURN_SECRET), { name: 'HMAC', hash: 'SHA-1' }, false, ['sign']);
    const sig = await crypto.subtle.sign('HMAC', key, new TextEncoder().encode(user));
    const credential = btoa(String.fromCharCode(...new Uint8Array(sig)));
    const urls = ['turn:turn.example.com:3478?transport=udp', 'turn:turn.example.com:3478?transport=tcp', 'turns:turn.example.com:5349?transport=tcp'];
    return new Response(JSON.stringify({ iceServers: [{ urls, username: user, credential }] }), { headers: {
      'Content-Type': 'application/json', 'Cache-Control': 'no-store', 'Access-Control-Allow-Origin': 'https://your-site.example' } });
  }
};
```

with the Worker secret `TURN_SECRET` set to the same value as `static-auth-secret`, and `window.ENDLESS_CLAY_ICE_URL` pointing at the Worker.

### Check that it works

1. **The relay answers:** open <https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/>, add your `turn:` address with its username and password (for Routes A and B, take one from the credentials address's answer), and press **Gather candidates**. A line of type **relay** means it works. No relay line: check the password, the ports, and `external-ip`.
2. **The app uses it:** for a test, force everything through the relay by adding `iceTransportPolicy: 'relay'` inside `config` in `js/config.js`, e.g. `{ config: { iceServers: [ … ], iceTransportPolicy: 'relay' } }`. Link a phone on mobile data (Wi-Fi off) to the headset, and join a room from it. If both work, the relay is doing its job. **Remove `iceTransportPolicy` afterwards**, so devices that can connect directly still do.
3. If the credentials address can't be reached, the app logs "TURN credentials unavailable" in the browser console and links without a relay, so nothing breaks outright.

## Privacy

The full text is in `privacy.html` (linked from the help card in the game and from the phone app). In short:

- No accounts, ads, analytics or tracking, and no server that stores players' things.
- Worlds, photos, sounds and settings stay on each player's device until they delete them.
- The camera is used only for **Take photo**, and the phone app's microphone only while recording, both after the browser asks.
- Rooms and the phone link connect devices directly (encrypted WebRTC). PeerJS's public matchmaking server sees a random device ID and IP address while connecting. People in a room see each other's chosen name and avatar colour, receive world changes, and can see each other's IP address, as in most multiplayer games.
- Social billboards load the platform's own player, under that platform's privacy policy.
- GitHub Pages hosts the files and may keep security logs, under GitHub's privacy statement.
- Not directed at children under 13. Questions go to the repository's Issues page.

If any of this changes (adding analytics, accounts or a server that stores things), update `privacy.html` and its date at the same time.

## Changing the code

The files in `js/` are the full, readable source. Edit them and upload again. The offline cache serves the old copy instantly and fetches the new one in the background, so a change appears from the second launch after upload. To make it appear on the very next launch, change the `CACHE` name at the top of `sw.js` (any new value).
